# Product Mode

Use this framework for SaaS, AI tools, apps, platforms, plugins, services, and operational workflows. Select only the sections needed for the user's decision; do not inflate a quick question into a long report.

## Analysis Framework

### 1. System Thesis

- Define what the product actually is beyond its category label.
- State the core promise and the narrowest credible reason it exists.
- Name the strategic bet that must be true for it to win.

### 2. Users and Jobs

- Identify primary and secondary segments.
- Describe functional, emotional, and social jobs only when supported.
- Locate the trigger moment, usage context, frequency, and switching event.

### 3. Value and Return Loop

Model the main loop as:

`Trigger -> Input -> Product work -> Visible value -> Return reason`

Also inspect acquisition, activation, retention, expansion, and network effects. If a loop is absent, say so instead of forcing one.

### 4. Product Architecture

- List core entities and their relationships.
- Identify the primary surfaces, navigation model, and state transitions.
- Explain which entity is the system of record and where data or intent enters and leaves.

### 5. UX and Craft

Name concrete, transferable decisions rather than adjectives:

- latency and feedback behavior
- information hierarchy and density
- defaults versus configuration
- interruption and notification stance
- error recovery, trust, and reversibility
- accessibility and cross-device behavior

For each pattern, explain what it enables and what it costs.

### 6. Business and Growth System

- Revenue model and buyer versus user.
- Free/paid boundary and monetization entry point.
- Acquisition channels, product-led or sales-led motion, and expansion vectors.
- Alignment or tension between user value and monetization.

### 7. Competition and Moat

Compare against three to five real alternatives on decision-relevant dimensions. Include non-consumption or manual workflows when they are the true competitor.

Separate:

- temporary advantage: novelty, timing, distribution, pricing
- operational advantage: speed, content, data, integration, workflow lock-in
- durable moat: network effects, proprietary data, ecosystem, regulation, brand trust

### 8. AI and Human Task Division

For AI products, map each important task to:

| Task | Human judgment | AI role | Failure cost | Required control |
|---|---|---|---|---|

Classify AI as assistive, embedded, or autonomous. Judge grounding, observability, correction, fallback, and whether automation removes work or merely moves it into review.

### 9. Metrics

Infer metrics only when useful and label them as inference:

- one unit-of-value North Star
- two or three controllable input metrics
- one guardrail
- one likely blind spot

Avoid fabricated numbers and vanity metrics.

### 10. Friction, Risk, and Opportunity

- Name the three highest-impact weaknesses.
- Build risks from evidence: severity, likelihood, time horizon, and mitigation.
- Propose opportunities at three levels: bounded improvement, strategic shift, and optional high-risk bet.
- Tie every recommendation to a mechanism and a measurable result.

## Product Verdict

End by answering:

1. Why does it win today?
2. Where does it break first?
3. What is genuinely difficult to copy?
4. Is it useful for the user's decision or project now?
